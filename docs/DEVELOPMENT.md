# prompt-jump 개발 과정

이 문서는 `prompt-jump`가 지금 모습이 되기까지의 과정을 **요구 → 문제 → 원인 → 해결** 순서로 기록합니다. 버전마다 무엇을 바꿨는지와 함께, *왜* 그렇게 바꿨는지(근거와 트레이드오프)를 남기는 것이 목적입니다.

- 개발 환경: Claude Code 2.1.295, macOS, fullscreen 렌더러
- 개발 방식: Claude Code 세션 안에서 mod를 작성하고, 사용자가 실제 세션에서 테스트한 뒤 문제를 알려 주면 고치는 반복

---

## 0. 출발점: "예전 프롬프트로 바로 돌아가고 싶다"

**요구**
대화가 길어지면 예전 프롬프트를 다시 보려고 계속 스크롤해야 했습니다. 목록에서 고르면 그 위치로 바로 가는 방법이 필요했습니다.

**기존 기능 조사**

| 기능 | 할 수 있는 것 | 한계 |
| --- | --- | --- |
| `Ctrl+O` transcript 모드의 `{` `}` | 이전·다음 프롬프트로 한 칸씩 이동 | 목록에서 골라 바로 갈 수 없음 |
| `Ctrl+O` 후 `/` 검색 | 키워드로 찾기 | 프롬프트 목록이 아님 |
| `Ctrl+R` | 예전 프롬프트 *텍스트* 검색 | 대화 속 *위치*로 가지 않음 |
| `Esc Esc` / `/rewind` | 보낸 프롬프트 목록 표시 | 되감기용. 잘못 고르면 대화가 잘림 |

결론: "목록에서 골라 위치로 이동"하는 기능은 없었습니다.

**최종 요구사항**: `Ctrl+R`은 그대로 두고, 예전 프롬프트를 골라 그 위치로 이동하는 부가 기능을 만든다.

## v0.1: `/jump` 패널

**설계 결정**

| 결정 | 근거 |
| --- | --- |
| `Ctrl+R` 다이얼로그를 확장하지 않고 `/jump` 명령으로 별도 패널 제공 | `Ctrl+R` 검색창은 엔진 내부 다이얼로그라 mod가 끼어들 렌더 지점이 없음 |
| 프롬프트 id는 `UserMessage` 행의 `ui.render` hook에서 수집 | `$.ui.scroll({ to: { requestId } })`가 요구하는 값이 행의 `requestId`(메시지 id) |
| 이동 후에도 패널을 닫지 않음 | 닫으면 도킹 폭이 바뀌어 다시 줄바꿈되면서 스크롤 위치가 밀림. 여러 프롬프트를 연달아 오갈 수 있는 장점도 있음 |
| 명령 결과로 `{}` 반환 | `{ text }`를 돌려주면 대화 기록과 모델 컨텍스트에 남음 |
| `immediate: true` | Claude가 응답하는 중에도 열 수 있게 |
| 글자 수가 아니라 터미널 셀 폭으로 자르기 | 한글은 한 글자가 2칸이라 글자 수로 자르면 줄바꿈되어 목록이 깨짐 |
| 스크롤 실패 시 토스트 | 거부(`{ deny }`)와 예외 모두 패널을 깨뜨리지 않게 |

**문제**: 처음 만든 mod는 그 세션 전용 폴더(`~/.claude/dev-mods/<세션id>/`)에 있어 다른 세션에서 로드되지 않고, 30일 뒤 자동 삭제 대상이었습니다.
**해결**: 고정 위치(`~/.claude/mods/prompt-jump`)로 옮기고 `settings.json`의 `env.CLAUDE_CODE_PLUGIN_DIRS`에 등록했습니다. 새 프로세스의 `claude plugin list`에서 `prompt-jump@inline ✔ loaded`로 확인했습니다.

**테스트 키트의 한계**: 테스트 키트에는 대화 행 스크롤 구현이 없습니다(`no implementation for ui.scroll`). 그래서 성공 경로 대신 "실패해도 패널이 깨지지 않고 토스트를 띄운다"를 테스트하고, 실제 이동은 실제 세션에서 확인했습니다.

## v0.2: 정렬, 되감기, 번호 필터

사용자가 실제로 써 보고 세 가지를 알려 줬습니다.

### 문제 1. 가끔 대화 순서가 섞인다

**원인**: 목록 순서를 "화면에 처음 그려진 순서"(Map 삽입 순서)로 정하고 있었습니다. fullscreen 렌더러는 화면 밖 행을 스크롤해서 보일 때 그리기 때문에, 예전 프롬프트가 나중에 목록 뒤(=최신 쪽)에 붙었습니다.

**해결**: 순서의 기준을 엔진이 가진 현재 대화 `$.session.messages()`로 바꿨습니다. 화면 행은 이동할 id를 얻는 데만 씁니다.
- `$.session.messages()`에는 메시지 id가 없어서, 화면 행과 **텍스트로** 짝짓습니다.
- 줄바꿈이나 블록을 잇는 방식이 달라도 맞도록 공백을 모두 뺀 값을 비교 키로 씁니다.

### 문제 2. 되감기(rewind)한 프롬프트와 명령이 목록에 나온다

**근거**: 세션 기록 파일(jsonl)을 열어 보니, 사용자가 되감은 프롬프트("dev-mods에 있는 복사본 지워줘")가 `parentUuid` 체인에서 벗어난 버려진 분기에 남아 있었습니다. 화면 행만 모으다 보니 이런 프롬프트도 목록에 계속 남았습니다.

**해결**
- `$.session.messages()`에는 버려진 분기가 들어 있지 않으므로, 여기서 짝을 찾지 못한 프롬프트는 자연히 빠집니다.
- 같은 텍스트가 여러 번이면 **최신 메시지부터, 가장 나중에 그려진 행과** 짝짓습니다. 되감은 뒤 같은 프롬프트를 다시 보내는 흔한 경우에, 버려진 예전 행이 아니라 화면에 남은 새 행을 고르기 위해서입니다.
- 슬래시 명령 행은 전부 뺍니다. 화면 표시(`/plugin`)와 저장 형식(`<command-name>…`)이 달라 되감기 여부를 확실히 가릴 수 없기 때문입니다. `/Users/...`처럼 경로로 시작하는 프롬프트는 명령 이름 패턴(`/^\/[\w:-]+(\s|$)/`)에 걸리지 않아 그대로 남습니다.

### 요구 3. 번호를 입력하면 그 번호로 필터링

**해결**: 숫자만 입력하면(`12`, `#12`) 그 번호 하나만 남깁니다. 숫자에 다른 글자가 섞이면 텍스트 검색입니다. "숫자만 → 번호"로 정한 이유는 `12` 입력 후 `Enter` 한 번으로 바로 이동하게 하려는 것입니다. 앞자리 일치(prefix)로 하면 최신순 첫 항목이 `#129`처럼 엉뚱한 번호가 될 수 있습니다.

## v0.3: resume 후 목록이 비어 있음

**문제**: 세션을 종료한 뒤 `--resume`으로 돌아오면 목록이 비어 있었습니다.

**근거**: 세션 기록 파일에는 프롬프트 출처가 `{"kind": "human"}`으로 저장돼 있었습니다. 그런데 mod API의 출처 종류(`PromptOrigin`)에는 `human`이 없습니다. `composer`(터미널 입력) 표시는 실행 중에 새로 입력한 행에만 붙습니다.

**원인**: resume으로 불러온 행은 다른 출처 값(문서상 `unclassified`)으로 들어오는데, `composer`·`bridge`만 받는 **허용 목록** 필터가 전부 걸러냈습니다.

**해결**: **제외 목록** 방식으로 바꿨습니다. 사람이 입력하지 않은 출처(작업 알림, 예약 실행, 다른 세션·채널·플러그인 메시지)만 빼고, 출처 표시가 없더라도 보낸 사람(`from`)이나 작업(`task`) 정보가 붙은 행은 뺍니다. 뒤에 현재 대화와 텍스트를 맞추는 단계가 있어서 혹시 섞여 들어와도 한 번 더 걸러집니다.

## v0.4: resume 직후에는 "한 번 본 프롬프트"만 나옴

**문제**: 정렬과 번호 필터는 정상이지만, resume 직후에는 스크롤해서 한 번 본 프롬프트만 목록에 들어왔습니다.

**원인**: 목록 자체는 `$.session.messages()`로 만들 수 있지만, 이동에 필요한 id는 화면에 그려진 행에서만 얻고 있었습니다. fullscreen 렌더러는 resume 직후 화면에 보이는 행만 그립니다.

**검토한 대안**

| 대안 | 결과 |
| --- | --- |
| `$.session.messages()`에서 id 얻기 | id 필드 없음 |
| `session.append` 이벤트 | resume은 "불러오기"라 이 이벤트가 오지 않음 |
| `$.fs.read`로 기록 파일 읽기 | 4 MiB 넘는 파일은 거부. 이 세션 파일이 이미 약 3 MB |
| **`$.process.run(['grep', …])`** | 프롬프트 행만 골라 읽으므로 파일 크기와 무관 → **채택** |

**해결**
- `/jump`를 열 때 세션 기록 파일 위치를 계산합니다: `<설정 폴더>/projects/<프로젝트 루트의 영숫자 외 문자를 '-'로 바꾼 이름>/<세션 id>.jsonl`.
  - 폴더 이름이 200자를 넘으면 엔진이 잘라 해시를 붙이므로, 이때는 `find`로 세션 id를 찾습니다.
- 기록 파일에서 사람이 입력한 프롬프트 행에만 있는 `promptSource` 필드로 `grep`해서 id와 원문을 가져옵니다.
  - 실제 기록 파일에서 확인한 값: `typed`, `queued`, `suggestion_accepted`, 알림은 `system`. 슬래시 명령·도구 결과 행에는 이 필드가 없습니다.
- 기록 파일 후보 뒤에 화면 행 후보를 붙입니다(`mergeSources`). 두 id가 같으면 기록 파일 순서 그대로 쓰고, 혹시 다르면 같은 텍스트끼리 짝지을 때 화면 행(이동이 확인된 id)이 우선합니다.
- 현재 대화 여부와 순서는 계속 `$.session.messages()` 기준입니다(4096개를 넘으면 오래된 것부터 빠짐).
- 기록 파일을 못 읽으면 화면 행만으로 동작합니다.

**검증**
- 테스트 15개 통과: 그려진 행이 하나도 없는 resume 상황, 되감기, 슬래시 명령, 알림, 잘린 줄, 번호·텍스트 필터, id 체계가 다를 때의 우선순위.
- 실제 세션 기록 파일에 같은 경로 계산과 추출 규칙을 적용해 프롬프트 15개가 추출되는 것을 확인했습니다.
- 사용자가 실제 세션을 종료하고 `--resume`으로 돌아온 뒤, 스크롤하지 않아도 이전 프롬프트가 목록에 나오는 것을 확인했습니다.

## 현재 구조

```
/jump 실행
  ├─ $.session.messages()          → 현재 대화의 사용자 메시지 (순서·포함 여부의 기준)
  ├─ 세션 기록 파일 grep             → 모든 프롬프트의 id·원문 (resume 직후 포함)
  ├─ 화면에 그려진 UserMessage 행    → 이번 프로세스에서 본 행의 id·원문
  └─ 텍스트로 짝짓기 → [{ id, text }] (오래된 → 최신) → $.state

패널 렌더
  └─ 검색어/번호로 거른 뒤 최신순 표시 → 선택 시 $.ui.scroll({ to: { requestId } })
```

## 남은 과제

1. **`promptSource` 의존 줄이기**: `session.append` 이벤트(공식 API: `door: 'prompt'`, `uuid`)로 프롬프트가 기록되는 순간 id를 받아 `$.store`(세션 간 유지되는 저장소)에 세션별로 저장하고, resume 때 그것을 읽습니다. 기록 파일 파싱은 그 이전 세션을 위한 대비책으로만 남깁니다.
2. **Remote Control(모바일·웹) 지원 검토**: 렌더 화면 종류에 `mobile`(Claude 모바일 앱)은 있지만 웹 브라우저는 없습니다. 모바일 화면에는 `Input`이 없으므로 `/jump 검색어` 인자로 거르는 방식이 필요합니다.
3. **패널 문구 다국어화**: 지금은 한국어 고정입니다.

## 배운 점

- **"그려진 순서"는 데이터가 아니다.** 가상 스크롤 화면에서 렌더 이벤트는 사용자가 어디를 봤는지에 따라 달라집니다. 순서와 포함 여부는 엔진의 대화 데이터로 정해야 합니다.
- **저장 형식과 실행 중 표시는 다를 수 있다.** 같은 프롬프트라도 실행 중에는 `composer`, 저장 후 불러오면 `human` → `unclassified`로 옵니다. 허용 목록보다 제외 목록이 이런 차이에 강합니다.
- **실제 데이터로 가설을 확인한다.** 되감기 분기, 출처 값, `promptSource` 값은 모두 실제 세션 기록 파일을 열어서 확인한 근거로 설계했습니다.
- **테스트 키트가 흉내 내지 못하는 부분은 실제 세션에서 검증한다.** 대화 행 스크롤처럼 키트에 구현이 없는 동작은 실패 경로만 테스트하고, 성공 경로는 실제 사용으로 확인합니다.
